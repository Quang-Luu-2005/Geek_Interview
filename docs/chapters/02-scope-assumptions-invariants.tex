\section{Implemented Scope}
The submission covers concert browse/detail, category inventory, transactional
booking creation, voucher application, customer booking lookup, confirm/cancel,
operator monitoring and guarded changes, minimal concert/category/voucher
creation, and automated expiry. Real authentication, payment, seat maps,
notifications, and multi-region operation are excluded.

\section{Business Rules}
These rules express user/product policy rather than concurrency guarantees:

\begin{itemize}[leftmargin=*]
  \item requested quantity is positive and each category belongs to the concert;
  \item only a published, future concert can be booked;
  \item voucher status, time window, scope, and per-user policy must match;
  \item the server owns price, discount, and total calculations;
  \item a live reservation may be confirmed or cancelled only before expiry;
  \item operation changes require an elevated role, a valid transition, and an audit reason.
\end{itemize}

\section{Non-Goals}
The assessment does not implement production identity, real payments/refunds,
seat selection, notification delivery, full administration CRUD, analytics,
multi-region active-active data, or event-broker infrastructure. These
boundaries keep the evidence focused on finite-resource correctness.
