The assessment backend is designed around a small number of explicit guarantees rather than a large number of features. PostgreSQL provides the consistency boundary for ticket inventory, voucher quota, booking state, and idempotency. The modular monolith keeps the critical booking transaction understandable and testable, while optional patterns such as scalable expiry workers and transactional outbox processing provide a credible path toward production evolution.

The final submission should be evaluated not only by API coverage, but by the evidence that critical invariants hold under concurrency, retries, failed transactions, and lifecycle races. The accompanying Swagger/OpenAPI documentation, Postman collection, local setup guide, test evidence, and architecture decision records are intended to make that evidence reproducible for the reviewer.
