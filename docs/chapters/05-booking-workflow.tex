\section{Transaction Boundary}
The following operations belong inside one transaction:
\begin{itemize}
  \item ticket inventory reservation;
  \item voucher quota reservation and redemption record;
  \item booking and booking-item persistence;
  \item any audit row that must be consistent with the transition being made.
\end{itemize}

External calls such as email, analytics, or a payment provider must not extend the core DB transaction. They should occur after commit or through an asynchronous reliability pattern such as a transactional outbox.

\section{Multi-Category Reservation}
When a booking contains multiple categories, category identifiers are normalized and processed in a deterministic order. This reduces deadlock risk and ensures the request is all-or-nothing: failure to reserve any category causes the transaction to roll back previously reserved categories automatically.
