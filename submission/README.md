# Task 12 — Documentation & Submission Package

This folder is the reviewer entrypoint for the completed assessment. The
repository itself is the source of truth; this manifest points to canonical
files instead of copying them into a second, potentially stale tree.

Logical package layout:

```text
submission/README.md        # this handoff manifest
docs/                       # design, API, security, test and report sources
openapi/openapi.yaml        # contract
postman/                    # environment, customer and operations collections
database/                   # migrations and deterministic seed
src/                        # implementation
tests/                      # unit, integration and concurrency suites
test-results/               # committed evidence indexes
```

## 3. Reproduction checklist

From a clean checkout:

```bash
npm ci
docker compose up --build -d
npm run db:reset
npm run format:check
npm run lint
npm run typecheck
npm run test:unit
npm run test:integration
npm run test:concurrency
npm run build
npm run verify:submission
npm run demo:wow
```

Then verify `GET /health/ready`, import the Postman environment and collections,
and run the customer flow followed by the operation flow. `npm run test:load` is
an optional k6 benchmark and is documented separately because it needs k6 or
the Docker k6 image. `npm run demo:wow` is the deterministic four-scenario
correctness showcase; `npm run demo:smoke` is the non-destructive API smoke
journey and requires a running API and seeded database.

## 4. Deliberate exclusions

Build output (`dist/`), dependency folders, editor metadata and transient test
logs are not submission artifacts. The committed `test-results/` summaries are
the reproducible evidence index; raw generated output may be regenerated by the
commands above. No credentials or access tokens are stored in this package.

## 5. Final handoff checklist

- [x] A reviewer can start from one README and follow only repository links.
- [x] Database IDs used by the Postman environment are deterministic after
      `npm run db:reset`.
- [x] API examples cover browse, booking, idempotent retry, confirmation,
      cancellation, operations, publishing and voucher creation.
- [x] Current behavior is distinguished from production evolution in the
      assumptions/limitations and security documents.
- [x] Test and performance evidence records environment, commit and expected
