OpenAPI is the complete machine-readable contract and Postman contains the
executable workflows. This chapter highlights only the endpoints that expose
the design's important boundaries.

Operation routes require \code{OPERATOR} or \code{ADMIN}. Manual terminal
commands start from \code{RESERVED}; cancellation/expiry release resources in
the same transaction and every successful command appends status history.
Update/delete administration is intentionally omitted because historical
pricing and voucher-version rules are unspecified.

\section{Availability Semantics}
Read availability is an informational snapshot and can become stale
immediately. The authoritative decision is the conditional inventory update
inside \apiendpoint{POST /api/bookings}.

\section{Error Contract}
\begin{lstlisting}[caption={Representative business error}]
{
  "code": "INSUFFICIENT_TICKET_INVENTORY",
  "message": "Requested ticket quantity is no longer available",
  "details": { "ticketCategoryId": 10 },
  "traceId": "..."
}
\end{lstlisting}

Expected sold-out, voucher, idempotency, ownership, and rate-limit conflicts
produce stable documented 4xx responses rather than generic 500 errors.
