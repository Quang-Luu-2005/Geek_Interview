\section{What Was Deliberately Not Chosen}
\subsection{Microservices}
The stated traffic and assessment time frame do not justify distributed deployment, service discovery, inter-service retries, and cross-service transaction complexity for the core booking path.

\subsection{Redis Distributed Lock for Inventory}
Inventory is already authoritative in PostgreSQL. Adding a Redis lock would introduce a second coordination system and additional distributed failure modes without a demonstrated need.

\subsection{Kafka as a Baseline Requirement}
Kafka is useful when asynchronous integrations and independent consumers justify it. It is not required to make ticket reservation correct at the stated load. A transactional outbox documents a safe evolution path if event-driven integration becomes necessary.

\section{Decision Review and Revisit Triggers}
Each ADR records context, alternatives, decision, rationale, consequences, and a
trigger for reconsideration. The decision is therefore a current fit, not a
claim that the selected technology is universally superior.
