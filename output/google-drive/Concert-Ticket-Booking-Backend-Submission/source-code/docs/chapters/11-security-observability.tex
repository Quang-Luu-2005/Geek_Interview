\section{Security Boundary}
Every customer or operation request requires a syntactically valid
\code{x-user-id} that exists in the seeded \code{users} table. Customer routes
require \code{CUSTOMER}; \code{/api/admin/**} requires \code{OPERATOR} or
\code{ADMIN}. Booking reads and customer commands include the customer ID in
the lookup predicate, so another customer's booking is not disclosed.

This header is assessment-grade identity injection, not authentication. A
production deployment must derive the same subject/role from a verified JWT,
OIDC provider, or trusted gateway. Existing ownership and RBAC checks remain
necessary after that replacement.

Validation pipes reject malformed DTOs and non-whitelisted fields. The booking
service rejects unpublished concerts, cross-concert categories, invalid
quantities, untrusted price inputs, and invalid voucher policy. Configuration
comes from environment variables; no runtime secret or private key is committed.
Errors never expose stack traces, SQL, request hashes, or stored replay bodies.

\section{Reliability Controls}
Correctness comes from short ACID transactions, database constraints,
conditional writes, bounded classified DB retries, and idempotency. Liveness is
process-only; readiness checks PostgreSQL and returns \code{503} when the API
cannot commit. Controlled sold-out/voucher/idempotency/rate-limit outcomes use
stable 4xx contracts rather than being counted as infrastructure failures.

The process-local booking-attempt limiter defaults to 60 attempts per customer
per 60 seconds and returns \code{429} with \code{Retry-After}. It reduces one
instance's abuse/retry pressure but never replaces inventory or idempotency
correctness. Multi-instance production requires a shared gateway/Redis policy.

\section{Observability}
The API validates, creates, and propagates \code{X-Request-ID}; responses and
standard errors expose the same correlation value. One-line JSON logs include
bounded request/event fields and omit request bodies, access tokens, voucher
codes, and payment data.

\code{GET /metrics} exposes low-cardinality Prometheus text counters including
HTTP totals, booking attempts/successes/replays/failures, sold-out and inventory
conflicts, voucher exhaustion, idempotency conflicts, and expired bookings.
These counters are in-process and reset on restart.
